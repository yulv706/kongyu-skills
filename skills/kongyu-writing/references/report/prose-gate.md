# 中文成稿：自然度与读者镜头

适用：新写或大幅改写的中文报告段落、说明文字和参与者叙事。规则只检查句子是否自然、读者镜头是否一致；内容的结构和文体规则见各文体 ref。

## 改写的三种方式

- **轻改**：保留结构，修正句子。
- **重写**：结构套路化或不可用时，重建段落。
- **只给建议**：用户只要指导时，给具体改法和短例，不整篇重写。

不引入新事实、虚构经历、夸张情绪或过度口语。自然感来自具体信息、节奏和省略。

## 交付前检查

1. 去掉空泛拔高：标志着、体现了、彰显、深远意义、持续影响。
2. 去掉宣传口吻：无缝、强大、充满活力、令人叹为观止。
3. 去掉模糊归因：专家认为、行业报告显示、观察者指出，除非有来源。
4. 拆开机械结构：不仅……而且……、三段式罗列、挑战与未来展望。
5. 去掉聊天残留：当然、希望这有帮助。
6. 技术、学术和运维文字保持清楚、可核验。
7. 句子节奏有变化，但不为变化而加修饰。
8. 指令用直接动词、主动主语；拆开挤在一起的逗号从句；“这”“该”“其”指代不清时，重复名词。
9. 把空泛的成功说法换成测量数字、可执行的命令、文件名或真实错误文本。代码、命令和引用原文逐字保留。

## 参与者叙事的读者镜头

适用于个人记录、访谈、聊天记录、复盘等参与者材料。先找发现，再定章节和语气。

1. 先完整读完材料，再选章节。
2. 每个候选发现写一行：读者没问出的问题、精确证据、它改变的关系或转折、反证或替代解释、把握程度、保留或舍弃。
3. 只保留改变理解、且经得起反证的候选。只按人物、时间或主题重新分组的，舍弃。
4. 正文用读者看得懂的场景和普通称呼。机器标识、分析员的评分字段放在核验层。
5. 读者镜头保持一条顺序：当时看见了什么，当时怎样理解，后来出现了什么参照，旧经验因此怎样变化，还剩什么不确定。
6. 标题写变化、张力或被解释的问题；开头落在一个具体的处境里。
7. 不写从外部分析员视角、已经知道结局的回望；不写解释机位和写法的开头。

标题和开头的拒收样例：标题“后来才看见的几件事”“我终于明白了什么”；开头“本报告采用回望机位”“下面先说明视角与写法”。

没有候选能通过时，改用忠实的摘录、时间线或来源索引，并直说边界，不把整理包装成发现。

## 成稿形状提醒

报告不套用创意散文的标点硬禁令。新写或大幅改写的自然段可运行 `python scripts/check_prose.py --mode contextual <稿件路径>`，只复核翻案腔变形、同构排比、名词化、连词密度、句长变异和「」金句密度。专业术语、必要清单和操作步骤命中时保留。

## 验证

报告界面类交付要核对源层和读者层一致。条件允许时，检查渲染后的顺序、窄屏溢出、焦点状态和文字是否装得下。不声称做过浏览器或截图验证，除非真的做了。
