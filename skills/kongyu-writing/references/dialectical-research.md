# 思辨研究模式：六步产物协议

本 reference 只在 `kongyu-writing` 的“思辨研究模式”中读取。它把研究判断和文章表达拆开，避免在搜集材料时提前写结论，也避免成稿时无意中改变已经裁决的主张。

## 适用范围

适用于观点文章、研究札记、决策备忘和其他需要先查证、再论证、再写作的非学术长文。普通报告、纯创作、文献综述和学术论文沿用各自的现有路由。

用户可以直接指定阶段名，也可以要求跑完整链路。没有明确要求完整链路时，只运行当前阶段及其必要的前置阶段。

## 共同协议

所有产物放在用户指定的项目或工作区目录中，不写入 skill 安装目录，也不擅自新建工作区根目录。每个产物开头保留最小状态信息：

```yaml
stage: osint | toulmin | debate | ensemble | adjudicate | monroe
status: draft | ready | pending-human | approved | rejected | skipped
parent: 相关上游产物或版本
updated: YYYY-MM-DD
```

阶段只写一种持久产物。聊天中可以报告状态，但不能借聊天摘要偷偷产生第二份结论文档。后续阶段优先传递 ID 和增量，不重复注入未变化的全文。

另维护一份 `argument-graph.md` 作为可恢复状态，不作为第七个研究阶段。它只索引 `source_id`、`claim_id` 和 `motion_id`，不复制来源正文或提前写文章。中断后先读它，再按 `stale_ids` 重算受影响节点。

| 字段 | 内容 |
|---|---|
| `contract` | 核心主张、读者、举证责任和利害；未确定的字段写未知 |
| `ladder` | 主张层级、父主张和当前状态 |
| `warrants` | 每个承重主张连接证据的规则；缺失时标 `missing` |
| `objections` | 最强反驳、反证和未解决冲突 |
| `scope` | 主张成立的范围，以及是否发生范围漂移 |
| `decisions` | 已批准、可存疑、否定或待人工决定的节点 |
| `stale_ids` | 上游变化后必须重算的下游 ID |

没有 `source_id` 的事实不能进入承重主张。证据存在但 `warrant` 缺失，只能标为未连接，不能算已支持。草稿里的核心判断必须能回到一个已裁决节点；新事实、新主张或范围变化先回写来源和主张，再标下游过期。


## 六个阶段

### 1. `/osint` → `sources/`

目标是建立证据库，不是解释证据。

每条记录至少包含：

| 字段 | 内容 |
|---|---|
| `source_id` | 稳定的来源 ID |
| `fact` | 来源明确支持的事实；来源本身的观点写成“来源主张……” |
| `locator` | URL、文件路径、页码、段落或其他可复核位置 |
| `event_time` / `published_time` | 事实发生时间或来源发布时间；不确定时标明未知 |
| `credibility` | 来源类型、直接性、独立性和可复核性 |
| `conflict_ids` | 与哪条记录冲突，或留空 |
| `retrieved_at` | 本轮获取时间 |

禁止写主张、因果解释、立场判断、推荐和文章段落。若事实尚未核实，记录为待核实或冲突，不用推测填平。

### 2. `/toulmin` → `claims.md`

把 `sources/` 编成主张账本。每条主张使用稳定的 `claim_id`，至少记录：

| 字段 | 内容 |
|---|---|
| `claim` | 要让读者接受的判断 |
| `evidence_ids` | 支持它的 `source_id` 列表 |
| `warrant` | 为什么这些证据能够支持该主张 |
| `backing` | 支撑论证规则的依据或背景 |
| `qualifier` | 范围、条件和置信程度 |
| `rebuttal` | 反例、反驳和失效条件 |
| `status` | supported、contested、unsupported 或 pending |

不得把没有 `source_id` 的事实写成已成立证据。语义改稿、删改和降级都对照 `claim_id`，不能只对照句子表面。

### 3. `/debate` → `motions.md`

把一个争议主张变成一个动议。一次只审一个 `motion_id`，记录：动议文本、支持理由、反对理由、修正案、少数意见、尚未解决的问题和本轮状态。

辩论不能凭空增加事实。新事实先进入 `sources/`，再回到 `claims.md`。同一证据被重复改写而没有新增问题时停止本轮，不让对话变成无边界的模型自转。

没有实质冲突时可以跳过，但要在本阶段产物中记录“未运行及原因”，而不是伪造一场辩论。

### 4. `/ensemble` → `view-dist.md`

让不同角色或模型各自给出一版判断，专门暴露预期背离。每个 view 至少说明：解释、最强支持、最强反对、隐藏假设、边界和置信度；汇总区分共识、分岔和未决点。

不按文风、篇幅或多数票选出赢家，也不把“多个 view 都这么说”当成新证据。没有重要不确定性或分歧时可以跳过，并记录原因。默认使用最少的独立视角，只有在分歧仍影响裁决时才增加视角。

### 5. `/adjudicate` → `judgment.md`

这是人工闸门。对每条主张由用户或指定审阅者明确选择：`保留`、`可存疑`、`否定`，并写下依据、逻辑问题、隐藏假设、反例和剩余不确定性。

agent 可以整理 ballot、指出缺失检查和提出待决问题，但不能把 `pending-human` 改成 `approved`，不能代用户完成三分类，也不能以模型共识结案。用户在聊天中明确作出决定后，agent 可以按原意记录该决定，不替用户扩写理由。

### 6. `/monroe` → `draft.md`

只有 `judgment.md` 已获人工放行后才能写作。草稿回答：为什么现在值得写、张力在哪里、证据如何支撑、反事实是什么、下一步是什么。只使用已保留或明确标为可存疑的主张；否定主张不得回流成事实。

表达习惯、语气和否决写法只在这一层生效。草稿可以重新组织顺序和句子，但不能新增未进入 `sources/` 的事实、未进入 `claims.md` 的核心判断，或绕过人工裁决补一个更顺的结论。

## 运行与 token 闸门

- 默认按需运行，不因用户说“研究一下”就自动跑满六步。
- `osint` 只增量补来源；`toulmin` 只重算受影响的 `claim_id`。
- `debate` 只接收一个动议；`ensemble` 只在关键分歧或高不确定性存在时运行。
- 各阶段读取必要的字段和 ID，不重复携带整篇原文；来源正文只在需要复核时展开。
- 上游发生语义变化时，标记下游产物过期；不要沿用旧的 `judgment.md` 生成新稿。
- 缺来源、冲突未解、人工未裁决、路径不明或验证失败时暂停，并报告具体缺口。

## 完成条件

完整链路只有在以下条件同时满足时才算完成：

1. 事实有来源、时间和可复核位置，冲突没有被隐藏。
2. 核心主张能回溯到证据，并写明论证规则、限定词和反驳；`argument-graph.md` 的层级、担保和过期节点与此一致。
3. 争议动议已经结束或明确记录为未解决。
4. 多视角中的共识、分岔和置信度已保留。
5. `judgment.md` 有明确的人类决定；未决项没有伪装成结论。
6. `draft.md` 中没有越过裁决边界的新事实或新核心主张。

交付时分开报告已完成、待人工决定、证据不足、主动跳过和未验证部分。
