# 流云写作

面向真人读者的中文长文和技术文档都在这里落地。一个 skill 三个模式，共享同一组内核判断。

## 内核（三种模式共用）

1. 先有材料，再动笔。非虚构靠可核验的事实、数字、动作、原话与用户经历；虚构靠人物目标、行动、场景变化与世界规则。材料不够就研究、追问或缩短，不用重复解释灌字数。
2. 先有说话位置。作者凭什么知道，哪里在推测，哪一点有判断。查资料不写成亲历，猜测不写成内幕。第一人称表达判断不等于伪造第一人称经历。
3. 先有读者问题。读者看完上一步最想知道什么，文章就往那里走。技术文档还要说清读者读完能完成哪件事。不按固定五段搭架子。长篇知识讲解可用目录定位章节；开头直接说明主题，不逐项复述目录。
4. 自然中文打底。需要陈述事实、机制或判断的正文句，尽早交代谈论的对象及其动作、变化或关系；让已知信息接上新信息，不把主语和谓语隔在大段修饰两端。长句可以，但读者要能跟上。写操作说明时，拆开过长的逗号分句和多层修饰；“这”“该”“其”指不清对象，就重写对象名。白话优先，古意从词序、停顿和分寸里自然出现。
5. 去 AI 味。目标是让文字回到作者自己的事实、判断和节奏，不承诺任何检测器都无法识别。具体化夸大的重要性、宏大框架、广告词和模糊归因，少用只制造深度的空泛名词化表达、空泛系动词、被动句和幽灵主语；需要写动作的正文句说清谁做了什么，不删必要的术语或过程名称。拆掉没有真实对比的否定式排比、硬凑三段式、同义词轮换、聊天机器人套话和格式噪音。动作、细节和原话已经传出的情绪不要再解释，比喻落地后不翻译含义，不连续用短判断收尾。高频词、第一人称、口语、局部不完整和不确定性都按语境判断，不为“像人”补假经历、假细节、错别字或粗糙感。有样本时先比对句长、词汇、标点、惯用表达和思维节奏。改稿按“先删冗余并重组、复读找残留、修正交付”三遍组织；用户指出说教、解释过多或重写仍无改善时，先按 `references/revision.md` 的“第二遍”删改句段，不靠同义改写或扩充禁词表。用户只要作品时只交最终版本。
6. 证据边界。不把抽象推演当成新材料。不把同义改写当成推进。不把概率当事实。不把平均观点当个人判断。说到的范围和材料能支撑的范围一致。
7. 文字先定任务再定句法。标题和标签可命名对象、关系或过程；论证性标题和主题句可以提出有证据支撑的判断；操作标题与步骤应写清动作及对象。图中的对象、状态与关系也要各自标清。不要把“谁做什么”套到所有标题和标签，也不要为了名词形式藏起正文的动作。具体词形服从语境、体裁与读者理解，不机械移植英语标题语法。

## 模式分流

进入时先判断任务属于哪种模式。技术解释、多步骤说明或复杂知识讲解还要按 `references/report/explainer.md` 与 `references/report/tech-doc.md`选择语言约束和表达媒介；不把技术指令约束套到创意叙事。

### 报告模式

触发：报告/汇报/HTML汇报/收口报告/交付汇报/进度汇报, decision memo, progress/status page, closure/handoff report, evidence package, plan page, 或中文 HTML/报告交付物；交互式 HTML 网页/教学页/带练习、选项、图表和本地服务器的页面；用户明确要求中文自然度打磨。系统性 humanize/de-AI/unslop 请求可在 sepia 实际可用时叠加它；不可用时本 skill 自行完成改稿。

报告模式的核心是让读者在没有聊天历史、没读过材料的情况下，读完能弄清情况、做出决定或执行操作。下面七条是所有报告文体共用的原则。每种文体怎样落地、各有什么示例，见下方路由表中的 ref。

1. **读者的任务决定内容。** 先写清读者读完要回答什么、决定什么、执行什么。删掉不服务这项任务的内容；条件、范围和不确定性不删，紧贴结论写。
2. **判断出现在读者需要它的位置。** 读者第一次需要判断时，判断已经在那里，并带着它的对象、数字和条件；依据紧随其后。
3. **每个新东西在出现处接住。** 新名词、新数字、新指代，第一次出现时读者就能接上：先用读者已知的话，再给名称；数字带对象和参照；指代写到读者能找到的对象。
4. **结构和图让读者扫得到要点。** 不读正文，读者也能从标题、段首句、加粗和图中抓到全文要点。能用图表达的关系或比较，先用图；其次用表查具体数；文字用来解释。并列用列表，每段只做一件事。
5. **强调只留给改变判断的东西。** 加粗、图和标注只用于决定性的那一点。
6. **同一个东西一个名字。** 同一对象、指标、部件全文同名。不用口语称呼、项目内部代号或临时比喻。
7. **只写材料能支持的。** 原因没查到就写“原因未核实”；没有结果就写缺口；无须决策就写“暂不需要决策”。

| 文体 | 读者要做的事 | 读 |
| --- | --- | --- |
| 研究结果、实验总结、调研说明 | 知道做了什么、发现了什么、要决定什么 | `references/report/result.md` |
| 进度、状态、收口、交接、聊天状态回答 | 知道现在在哪、卡在哪、下一步谁做 | `references/report/status.md` |
| 决策备忘 | 在几个选项中作出选择 | `references/report/decision.md` |
| 知识讲解、概念学习、教程的概念部分 | 认识对象、理解关系、能复述或应用 | `references/report/explainer.md` |
| 中文 README、设计文档、接口说明、操作手册 | 完成一项任务，遇到错误能判断下一步 | `references/report/tech-doc.md` |

图的标准：有标题，标题写结论；有图注，写对象、口径和好坏方向；数字来自数据文件，不手填。装饰图、不承载关系或比较的图不画。

所有文体共用：`references/report/examples.md`（拒收样例与句子对照）、`references/report/delivery.md`（交付形式、双层读者、HTML 检查、读者标签）、`references/report/prose-gate.md`（中文成稿自然度、参与者叙事的读者镜头）。

交付前的冷启动检查：第一屏能说清这是什么、现在在哪里、证据能支持什么、不能支持什么、下一步做什么。实质报告末尾放一节，标题恰好为 `我们可能错了`，写依据最弱的判断和会推翻它的条件。

需要其他深度材料时：研究现状综合读 `references/research-landscape-synthesis.md`；HTML 外壳读 `references/report-shells.md`；浏览器内决策读 `references/interactive-decision-reports.md`；参与者叙事读 `references/participant-narrative-reports.md`；图引擎读 `references/docu-md-diagram-reference.md`。

### 创意模式

触发：知乎回答/论坛长帖/公众号文章/博客/评论/人物稿/历史稿/行业解读/新闻/产品解读/科普/教程/评测/个人叙事/小说/故事/对白/口播/演讲稿。

创意模式的核心是活人感。读者应当感觉对面有一个具体的人。这个人知道一些事，也有不知道的地方。他愿意讲细节，敢下判断，偶尔岔开一句，随后还能把话接回来。

默认现代创意散文中作者可改写的文字有严格语体约束（冒号、破折号、翻案句等）。剧本、对白、诗歌、经核实的逐字引语和报告模式不套用这组硬禁令。

这些禁令是本 skill 对创意散文的语体约束，不是对所有 AI 文本的统计判断。报告、学术或明确要求保留原有语体的文本不自动套用。

创意模式的完整规则和改稿流程见下方"创意模式详规则"。

### 思辨研究模式

触发：用户明确要求把研究或观点写作拆成证据、主张、审议、多视角、人工裁决和成稿阶段，或直接使用 `/osint`、`/toulmin`、`/debate`、`/ensemble`、`/adjudicate`、`/monroe` 这些阶段名。

这是本 skill 内的一个受控模式，不创建六个新 skill。它把中间产物限制为 `sources/`、`claims.md`、`motions.md`、`view-dist.md`、`judgment.md`、`draft.md`；每个阶段只写自己的产物。进入此模式后先读 `references/dialectical-research.md`，并维护可恢复的 `argument-graph.md`。

阶段顺序、跳过条件、人工裁决闸门和 token 预算以该 reference 为准。没有人工放行的 `judgment.md`，不得进入 `monroe` 写 `draft.md`。

### 参与者叙事（三种模式共用）

触发：用户要基于会话历史、个人材料或亲历叙事写参与者面向的复盘、洞察报告，或要求从采访中发现关系、机制、转折与矛盾。单纯整理采访、按时间编排经历或润色会话记录不触发发现台账；仍须忠实于原材料与当时的信息视野。

参与者是事件内部的读者，不是外面 analyst。复盘或洞察报告从参与者的信息视野写，不从全知视角回望；先完成覆盖与发现两份台账，再搭章节骨架。title 和开头进入具体情境，不解释视角、方法或报告设计。

写上述复盘或洞察报告前读 `references/participant-narrative-reports.md`。普通整理只借用其事实忠实、信息视野和机器标识处理规则。

## 模式选择规则

- 用户明确要求六步思辨研究链、主张账本、观点审议、证据到成稿，或使用上述六个阶段名 → 思辨研究模式；不要自动改写成普通文章。
- 用户要报告/汇报/状态/决策/收口 → 报告模式。
- 用户要中文 README、设计文档、接口说明或教程 → 报告模式的技术文档分支，并读 `references/report/tech-doc.md`；保留项目原有文档结构与术语。
- 用户要知乎/论坛/公众号/博客/故事/小说/口播 → 创意模式。
- 用户要基于亲历、会话或采访做参与者面向的复盘/洞察报告 → 参与者叙事的覆盖与发现 gate + 报告或创意模式（取决于交付形式）。仅整理、转写或润色时保持事实与信息视野，不强制发现台账。
- 用户只要最终文章而没有要求论证链 → 不强制运行六步模式，按交付形式选择报告或创意模式。
- 用户要研究现状、领域 survey 的综合源稿或图文组织，或指出“只是罗列论文、看不出研究现状” → 先读 `references/research-landscape-synthesis.md`，完成分类、证据覆盖与结果综合的分工；检索交给研究工具，正式学术论文段落交给 reader-centered-paper-writing，PPT 叙事与分页仍由 kongyu-ppt 负责。只有用户明确要求六步论证链时才启用思辨研究模式。
- 用户要 PPT/deck/演示文稿的故事、逐页规划或演示审查 → `kongyu-ppt`；可按需借用本 skill 的研究综合规则，但不自动另造长文。只有同时要求独立长文/报告时，本 skill 才负责那份文字源层。
- 报告里的自然中文散文需要去 AI 味 → sepia 可用时系统性 humanize/de-AI/unslop 可先路由它；不可用时不阻塞，直接按内核的三遍改稿流程和 `references/report/prose-gate.md` 的 Natural Chinese Prose Gate 处理。不用创意模式的硬禁令。
- 默认现代创意散文长稿写完后 → 跑 `scripts/check_prose.py` 检查适用的硬禁令；剧本、对白、诗歌、实验写作与需保留原话的稿件不以该脚本的硬失败作交付门。
- 报告 HTML 交付前 → 跑 `scripts/check-cold-start-gate.py` 做首屏结构冒烟，再人工核对读者问题、判断、证据、边界与下一步；脚本通过不代表语义通过。
- 模式不清时，看交付物形式：HTML 报告/状态页/决策备忘/交互式网页/教学页 → 报告模式（叙事+证据结构）；纯文字文章/帖子/故事 → 创意模式。交互式教学页的视觉布局再路由 kongyu-surface。

## 创意模式详规则

### 第一关先看作品靠什么站住

这一步先于提纲和动笔。用户要求的字数不能跳过它。

现实作品靠前两类材料，虚构作品靠第三类材料。混合创作先把两部分分开。

- 用户明确提供的经历、事实、数字、动作、原话与判断。
- 已经查到并能核验的案例、数据、产品流程、人物经历与时代条件。
- 虚构任务中，作者获准创造的事件、人物动作与场景变化。

现实稿里，模型临时想出的"比如有个人"、没有来源的典型场景、常识推演、抽象观点的后果、比喻与同义改写，都不能拿来撑篇幅。

虚构稿可以创造人物、现场和细节，不需要为它们寻找现实出处。每个主要段落或场景仍要有动作、选择、关系变化、信息变化或后果。只换景色和说法，没有事情发生，也不能拿来撑篇幅。

非虚构作品计划达到一千二百字时，先在内部逐条写出至少五件具体材料，并注明它来自用户哪句话或哪份可靠来源。只写一个概括性的类别不算。五件材料还要能组成一条实际过程，不能是五句相邻的道理。

非虚构稿列不出五件，就先别写长稿。这一轮不能输出标题和长文正文。目标字数、用户催促和"直接写"都不能把材料变多。

现实材料不够时，只能选择一种处理。

- 事实型题目有公开材料可查时，先研究，研究后重新计数。可用检索工具却没有检索，仍然算没有材料。
- 个人体验或私人判断需要用户材料，一次问完最多三个问题，此时不要同时交稿。
- 用户明确不许追问时，缩小题目，最多交一篇六百字左右的短答。宁可明显短于目标字数，也不能用假例子和重复解释填满。

现实稿动笔前记清每件重要材料从哪里来。说不出来路的内容不能负责托住事实段落。虚构稿改为检查每个场景由哪个人物目标、动作或变化托住，不给虚构细节伪造来源。不要把这些内部检查交给用户。

现实观点稿有一种高频错误要直接拦住。用户只给"输入更方便""声音能保留状态""AI 可以找回旧内容"这类三条抽象想法，又要求一千多字，这仍然只有三条材料。不能分别补上用途、意义、风险和未来，再写成十几段。应当先找真实产品、使用过程、研究或用户经历。找不到就问，用户不让问就写短答。

### 按任务读取

- 新写或大幅重写知乎回答、论坛长帖、公众号文章、博客、评论、人物稿和行业稿，读取 `references/forum-prose.md`。
- 真人、历史、新闻、产品、数据、评测、教程、商业信息和用户亲历，另读 `references/reality.md`。
- 小说、故事、虚构散文、对白和剧本，改读 `references/fiction.md`。用户要求帖子体小说或第一人称故事时，再同时读取 `references/forum-prose.md`。
- 短内容、个人叙事、教程、评测、口播、演讲、剧本、对白和诗歌等形式需要特殊处理时，读取 `references/formats.md`。
- 初稿完成后再读取 `references/revision.md`。不要在动笔前加载详细审稿规则。

不要为了保险一次加载全部参考文件，只读当前任务确实命中的部分。真正的混合任务可以读取多个文件，`references/revision.md` 仍留到初稿以后。创作时以正向目标为主，已经写在本文件里的交付禁令留到初稿完成后再逐项检查。

### 多条规则同时出现时

按下面的顺序处理。

1. 当前用户明确指定的文体、现实或虚构性质、语气和交付形式。
2. 作品对现实作出的承诺。现实内容服从事实边界，虚构内容服从人物、因果与世界规则。
3. `references/fiction.md`、`references/reality.md` 和 `references/formats.md` 中与当前任务直接相关的规则。
4. `references/forum-prose.md` 与本文件里的默认散文写法。
5. `references/revision.md` 的改稿规则与检查脚本的提醒。

具体文体覆盖通用写法。现实稿的来源要求不能压到纯虚构上，散文的完整主干不能压到诗歌分行和人物对白上。检查脚本只能执行已经写明的硬禁令，警告项不能替作者决定文体。

### 先确定作品对现实作出什么承诺

**现实写作**：真人、现实事件、数字、引语和用户经历都要核准。用户没提供的亲历、现场、对白和心理，不能补成事实。

**虚构创作**：可以创造人物、地点、现场、对白、心理和结局。人物、时间、因果与世界规则要前后接得上。

**混合创作**：先分开现实中必须准确的部分和可以创造的部分。只核会影响故事与现实判断的事实。

用户说了"小说""虚构""假设""随便编"，直接创作。用户要求真实、纪实、亲历或遵循历史，先核验再写。

### 动笔前先找到说话位置

在内部回答下面五件事，不把答案原样交给用户。

1. 谁在说这件事。他凭什么知道，又有哪些地方只是在推测。
2. 什么事情让他现在想说。可以是一条新闻、一次经历、一个疑问或一件一直想不通的小事。
3. 手里有哪些能托住文章的东西。优先找动作、数字、时间、地点、原话、失败、代价与后来结果。
4. 他对哪一点有明确判断。这个判断依据什么，又到哪里为止。
5. 读者知道上一段以后，最自然会追问什么。

现实稿的第三项太少，回到开稿前的材料检查。不要用哲理、象征、想象现场和重复结论补字数。六千字现实长文需要能展开多个阶段、案例或现实关系。虚构稿若缺少人物目标、行动和场景变化，回到 `references/fiction.md` 补出故事，不向用户索要不存在的现实出处。

现实材料不够时先停在这里。能查到公开材料就研究。作品依赖用户体验、情绪和私人判断，就一次问完下面三件事。

- 你和这件事实际发生过什么关系。
- 哪个瞬间、数字、动作或原话最让你在意。
- 你现在最想说的判断是什么。

不要先交一篇空稿，再期待用户往里补活人感。

现实稿要求直接写而且无法补材料时，宁可交一篇更短、更实的作品。篇幅是目标，材料边界是底线。虚构任务直接按授权创造，篇幅由事件和场景变化托住。

个人经历缺少关键材料时，最多问三句。用户明确要求不追问或直接出稿，就先研究，随后缩小题目或缩短篇幅，不能把新增经历安到用户身上。

### 第一稿直接带着人写

第一稿从具体说话者和材料出发。像给一个感兴趣但不了解此事的人解释，边讲事情，边处理他下一步会产生的疑问。

下面是现代白话散文的默认写法。诗歌、剧本、人物对白和实验写作服从具体文体规则，不能为了满足散文句法而改坏作品。

- 开头尽快碰到事情。可以直答，可以讲刚发生的一幕，也可以从一个反常的小事实说起。不要预告全文结构。
- 除非用户明确要清单或教程，不要先把题目命名成两个成本、三层原因、四个阶段。分类应当来自材料，不能拿分类代替文章。
- 一段先完成眼下这一件事。它可以讲动作、补背景、算一笔账、解释原因、承认疑点或给出判断。
- 新段落必须增加一件新东西。新的事实、新的动作、新的例子、新的区别或新的后果都可以。同一观点改换说法不算推进。
- 后一段接住前一段留下的问题。推进靠材料和因果，不靠"更深一层""真正的问题"之类路标。
- 先让主语和动作出现，再往后接时间、原因、条件和例子。长句可以有，读者要尽早知道谁做了什么。
- 让白话打底。古意从词序、停顿和分寸里自然出现，不靠生僻字、成串成语和硬塞典故。
- 动作、细节或原话已经把感情写出来，就停一下。不要追在后面替读者解释。
- 允许正常的重复、补充、自我修正和短暂岔话。每一处都要来自眼前内容，不能按固定间隔表演随意。
- 判断可以偏，可以有情绪。把依据放在附近，让读者知道这是作者的看法。
- 现实稿的幽默从事情自身的荒唐处出来，不另编笑话，也不给严肃材料强塞俏皮话。虚构稿的笑料要属于人物、关系和场景。
- 段落不必等长。普通地方用普通句子结束。单句成段只留给确实需要停一下的地方。
- 写到事情已经讲完就停。不要强装升华、首尾呼应或时代意义。前后照应只有在事物的作用或含义已经改变时才保留，正文持续处理过时代尺度时才允许在结尾回到这个尺度。不要在末段重新摘要全文。

用下面这组句子校准方向。

> 他毕业后离开上海，去了成都。那套量化程序已经跑过一段时间，他觉得可以全职试试。收入会不会稳定，当时没人知道。

这比"他关掉一条好走的路，把命运押上赌桌"更接近目标。前一种写法给动作、条件与风险，后一种写法只有姿势。

### 不要穿论坛服装

论坛感不等于"老铁""兄弟们""谢邀""泡杯茶慢慢说"。烟头、啤酒、冷馒头、深夜屏幕和突然响起的电话，也不能凭空替文章增加真实感。

现实稿里，没有来源的精确时间、神态、天气、房间摆设和对白都是假细节。假细节越具体，AI 味越重。虚构稿可以创造这些内容，细节必须跟着人物视角与行动走，不能只负责穿上论坛服装。

现实稿真正有用的是信息来路。写清作者在哪里知道这件事，起初哪里想错了，哪条材料改变了判断，哪一块到现在仍拿不准。只挑当前文章确实拥有的部分，不要凑齐。虚构稿的可信感来自人物怎样知道、误解和发现，不伪造现实来源。

### 成稿绝对不能出现（创意模式专用）

下面几项是默认现代创意散文中作者可改写文字的语体约束，覆盖标题、小标题、正文和图片说明。它们不覆盖用户指定的剧本、对白、诗歌、实验写作、必须保留的原有语体和经核实的逐字引语；这些形式仍检查事实与表达，但不为了清零标点或词形改坏内容。报告模式也不套用这些硬禁令。

- 不用中文冒号和英文冒号。网址、代码与无法改动的机器字段除外；只有引出人物直接原话时，冒号可作为人工例外，脚本仍会列出供复核。
- 不用破折号、双破折号和连接号式破折号。
- 不写翻案腔。硬句式包括"不是……而是……"、"并非……而是……"、"不在于……而在于……"、"与其说……不如说……"、"表面……实际……"、"看似……实则……"。伪装句式包括"你以为……其实……"、"回头才发现"、"说到底"、"答案恰恰相反"、"A不重要，重要的是B"和"真正……的是"；脚本只提醒，确认是先立误解再推翻后改成正面判断。"不只……还……""不只……也……"只在用来抬价时按翻案腔处理。
- 不用"说白了""说穿了""先说结论"。
- 不写三项以上同构排比。留两项，第三项换说法或删除；法规、步骤和必要清单不受影响。
- 不把动词名词化。"完成了对流程的优化""实现了效率的提升"要还原成具体动作和结果。
- 不把"更微妙的是"、"还有一层"、"只说对了一半"、"值得注意的是"、"需要指出的是"、"从某种意义上说"当成段落或句子的洞察路标。文字确实在说楼层、数量等本义时不受影响。
- 不用商业汇报和模型惯用黑话替普通事情抬价。`references/revision.md` 区分适用散文的硬停词与需要结合语境判断的专业/抽象词；检查脚本不得把后者自行升级成硬禁词。
- 非虚构内容不用仓库、抽屉、温度、死亡、坍塌、浪潮、钥匙、底座等借喻包装抽象概念。文章真的在写这些东西时不受影响。
- 经核实且必须逐字保留的原话按原样引用；不要为绕过语体检查而改写来源。

初稿写完以后再执行这些检查。修改违禁句时，先找它原本想说的事实，随后用普通句子说出来。不要寻找另一种漂亮句式替换。

适用的散文长稿可保存为 Markdown 或文本后运行 `python scripts/check_prose.py <稿件路径>`。脚本的硬失败只覆盖明确禁令和无歧义句式；翻案腔变形、同构排比、名词化、连词密度、句长变异、「」金句密度和抒情词都只作人工提醒。对不适用硬禁令的形式，运行 `python scripts/check_prose.py --mode contextual <稿件路径>`，全部结果只供复核，不以退出码阻断交稿。

### 交稿

去 AI 味改稿默认只交最终版本，除非用户另要来源、分析或审稿意见。不要展示三遍检查、残留清单、内部提纲和创作过程。

用户要求真实来源、写作分析或审稿意见时再附。现实稿只列对结论重要的来源，不把检索笔记塞进正文。

只服务当前作品。不建立长期作者画像，不生成个人规则库，不创建新的个人写作 Skill。
