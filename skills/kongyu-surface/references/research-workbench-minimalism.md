# Research Workbench Minimalism

适用场景：科研助手、搜索工作台、评估页、计划页、Agent 工作台，尤其是 Windows/Electron 文档工具这类以"当前任务"为中心的生产力界面。先看真实截图再判断，不用通用 SaaS 套件猜界面。

## 核心判断

- [ ] 如果页面让人第一眼感觉像"后台设置页""产品介绍页""仪表盘卡片堆叠页"，说明 reader entropy 过高
- [ ] 工作台页面应优先呈现：当前输入、当前动作、当前结果、低权重历史、低权重设置
- [ ] 解释、模块清单、重复标题、装饰性卡片，默认都应削弱或删除

## 反模式

- [ ] 避免圆角卡片墙、大白卡 + 重阴影 + 多层边框；默认做扁平工作区
- [ ] 避免设置区和内容区完全脱节，像悬浮后台控件
- [ ] 避免刷新、设置、模式切换各自用不同视觉语言
- [ ] 避免重复出现服务名称、模块名称、流程说明
- [ ] 避免结果区做成 dashboard 卡片流（应做成线性阅读内容）
- [ ] 避免右侧 SaaS dashboard 式副栏，历史区不得和主输入区视觉重量相同
- [ ] 避免输入区之外仍然有大量框框争夺注意力
- [ ] 少卡片、少胶囊、少虚线上传框；只有真实的边界或交互语义才保留容器

## 推荐模式

### 1. 统一壳层，克制内容区

全站统一 header 优先保留，不要为了单页单独发明一套顶部壳层。真正该优化的是内容区：主输入区、模式切换、刷新/设置、当前结果、最近任务。

### 2. 一条工具带解决头部控制

- [ ] 内容区头部做成一条内层工具带：左侧模式切换，右侧刷新/设置
- [ ] 确保这些控件同一层级、同一高度、同一字重、同一 padding、同一基线、同一按钮语法
- [ ] 不要让"设置"成为原生 details/summary 风格，除非已强制抹平浏览器默认行为；更稳妥的方法是普通按钮 + 独立弹层
- [ ] Vercel 式 ghost-first 控件适合这里：默认透明，hover 弱灰底，focus 双环；不要让刷新/设置/模式切换各自动画或各自配色

### 3. 输入框可以有边界，但应使用纸色

- [ ] 真正必要的输入框保留边界，但优先使用 XiaoLab 纸色系（`var(--paper-soft)`、与页面底色接近但略亮）
- [ ] 使用弱边框、轻 focus ring

### 4. 结果区应像文稿，不像卡片流

- [ ] 结果优先做成线性段落、轻分隔线、少量元信息
- [ ] 少卡片或无卡片；只有多个完全独立对象时才考虑弱卡片
- [ ] 如果必须有边界，优先 shadow-as-border：`0 0 0 1px rgba(0,0,0,.08)`；边界不应改变布局或抢走主输入区注意力

### 5. 右侧历史是低权重轨道

- [ ] 最近任务区更窄、更轻、更像时间线/列表
- [ ] 避免和主输入区一样重

## 验证清单

设计改动后，至少回答：

- [ ] 第一眼能不能立刻看出"现在要做什么"？
- [ ] 设置/刷新/模式切换是不是同一种语言？
- [ ] 有没有不必要的框在抢主输入区的注意力？
- [ ] 结果是不是更像阅读内容，而不是 dashboard？
- [ ] 页面是不是仍然服从 XiaoLab 统一 header？
- [ ] 颜色是否能压缩到灰阶 + 一个交互 accent + 小尺度状态点？
- [ ] 所有控件是否落在同一套 4px spacing、6px/12px radius、400/500/600 字重上？

- [ ] 如果答案是否定的，就继续删、继续弱化，而不是继续加样式
